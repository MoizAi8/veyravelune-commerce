# Security and privacy gates
- Server-only DB connection, auth secret, optional test Stripe secret and webhook secret. Validate required env on appropriate server entry points; no secret values in logs, public variables or repo. Rotate any accidental exposure.
- Auth.js supported integration; deny by default, server-side RBAC on every admin mutation/read, session ownership for order reads, secure cookie settings, CSRF/origin protection, rate limiting for login/checkout/contact using a shared backing mechanism or platform limits for public writes. If protections are not configured, disable affected public endpoints rather than claiming safety.
- Validate request size, content types, ID formats, quantities, currency, text lengths, search params. Escape user content; avoid raw HTML/unsafe SQL. Do not implement arbitrary remote image URL fetch; allowlist approved hosts or use local paths. Restrictive CSP compatible with Next/3D; test headers, no broad unsafe exemptions without documented reason.
- No real card data; public demo should prefill synthetic info, instruct users not to enter real addresses, avoid storing unnecessary contact data, set cleanup/retention. No real fulfillment. Guest references unguessable and owner-bound. No PII in analytics, error logs or portfolio screenshots.
- Public admin write access prohibited. Owner provisioned privately; show read-only example or screenshots if no safe admin account. Public demo writes may require rate limits, reset schedule or private gating to prevent abuse; do not allow uncontrolled stock exhaustion.
- Transactions, idempotency and integer cents mandatory. Test malicious price, negative qty, role escalation, cross-user order access, race, duplicate submission. Never run destructive migrations against production. Dependency audit, review findings; no blind force upgrade.
- Portfolio-ready does not mean commercially secure. Real payment, legal terms, taxes, shipping, privacy, load and penetration review are separate launch requirements.
